# YEGNA BINGO V51.5 — Global Round + Admin Security

## Global game
- One active `picking`/`running` round is enforced across all users and both legacy game entry points.
- The server/PostgreSQL is authoritative for round state, card reservations, called numbers, countdown timestamps, and settlement.
- Legacy active rounds are consolidated during migration v48; cards in obsolete active rounds are refunded before those rounds are settled.
- `games_one_global_active_idx` prevents two active rounds from being created concurrently.

## Admin security
- `SUPER_ADMIN_TELEGRAM_ID` is authoritative for Super Admin identity.
- Existing sessions are re-evaluated against the configured Super Admin Telegram ID.
- Normal users cannot access `/admin/*` endpoints; backend returns 403.
- Cross-user wallet access requires the admin `users_view` permission.
- Sub-admin creation, removal, and permission changes require Super Admin.

## Migration v48
The previous `migration-v43.sql` file was removed from the migration set because production already contains a different recorded v43 checksum. V43 only duplicated the `bot_conversations` table already created by v42, so fresh installs do not need it. Migration v48 performs the global-round consolidation and adds the single-active-round constraint without modifying an applied historical migration.
